# JFrog npm private registry

This note sets up a safe path to publish Funesterie npm packages to JFrog
Artifactory when npmjs access is not available.

## Recommended JFrog layout

Create these npm repositories in JFrog Artifactory:

```txt
funesterie-npm-local   local npm repo for private packages
npmjs-remote           remote proxy to https://registry.npmjs.org
funesterie-npm         virtual repo combining local + remote
```

Use the virtual repository URL for installs:

```txt
https://<tenant>.jfrog.io/artifactory/api/npm/funesterie-npm/
```

Use the local repository URL for private publishes:

```txt
https://<tenant>.jfrog.io/artifactory/api/npm/funesterie-npm-local/
```

This avoids false collisions with public npm versions proxied by the virtual
repository.

## What `frog.txt` contains

`C:\Users\Djeff\Desktop\frog.txt` currently contains base64-encoded license
blocks:

```txt
admin    -> Artifactory license block
password -> Xray license block
```

These are not login credentials. Do not paste them into `jf c add --password`;
that creates an invalid CLI config and Artifactory rejects requests with
`Request Header Or Cookie Too Large`.

## Cloud first

For the package registry, prefer JFrog Cloud:

```txt
https://trialhnuk69.jfrog.io/
```

The self-hosted JFrog Platform installer is useful later, but it is heavy. The
current official install page asks for a large machine profile (8 CPU, 16 GB
RAM, 300 GB fast disk). Keep that off the Seagate unless we explicitly decide to
dedicate space and IO to it.

Install or verify the JFrog CLI:

```powershell
$env:Path = "$env:USERPROFILE\bin;$env:Path"
jf --version
```

If a bad `funesterie` server config exists, overwrite it with a real JFrog
identity/access token:

```powershell
$env:JFROG_ACCESS_TOKEN = "<jfrog-access-token-or-identity-token>"
.\scripts\jfrog\Configure-JFrogCli.ps1 -Url "https://trialhnuk69.jfrog.io/" -Overwrite
```

Do not paste the contents of `frog.txt` as the CLI password. That file contains
Artifactory/Xray license blocks, not a login password or npm token.

Create the npm repository layout once:

```powershell
.\scripts\jfrog\Ensure-JFrogNpmRepos.ps1
```

Create a local env file from the example:

```powershell
cd D:\projets\funesterie
Copy-Item .\scripts\jfrog\jfrog.env.example.ps1 .\scripts\jfrog\jfrog.env.ps1
notepad .\scripts\jfrog\jfrog.env.ps1
. .\scripts\jfrog\jfrog.env.ps1
```

Generate an npm config that reads the token from the environment. For normal
installs, keep `JFROG_NPM_REGISTRY` on the virtual repository:

```powershell
.\scripts\jfrog\Write-JFrogNpmrc.ps1 -Force
```

The generated `.npmrc.jfrog` does not contain the token value. It contains:

```txt
@funeste38:registry=https://<tenant>.jfrog.io/artifactory/api/npm/funesterie-npm/
//<tenant>.jfrog.io/artifactory/api/npm/funesterie-npm/:_authToken=${JFROG_NPM_AUTH_TOKEN}
```

## Token troubleshooting

The tenant must be the active JFrog Cloud tenant:

```txt
https://trialhnuk69.jfrog.io/
```

If `jf rt ping` returns `OK` but repository creation fails with
`Token failed verification: signature`, the CLI reached the tenant but the token
does not verify against that tenant. Generate a fresh identity/access token from
inside the `trialhnuk69` UI, then rerun `Configure-JFrogCli.ps1 -Overwrite`.

If a short reference token fails with `Props Authentication Token not found`,
do not use it as the npm token. Use the full access/identity token generated by
JFrog for this tenant.

## Dry run

Run this first. It builds packages when they expose a build script and runs
`npm pack --dry-run --ignore-scripts`.

```powershell
.\scripts\jfrog\Publish-FunesteriePackages.ps1
```

If you only want package inspection without builds:

```powershell
.\scripts\jfrog\Publish-FunesteriePackages.ps1 -SkipBuild
```

## Publish

Only after the dry run is clean:

```powershell
$env:JFROG_NPM_REGISTRY = "https://trialhnuk69.jfrog.io/artifactory/api/npm/funesterie-npm-local/"
.\scripts\jfrog\Write-JFrogNpmrc.ps1 -Force
.\scripts\jfrog\Publish-FunesteriePackages.ps1 -Publish
```

After publishing, switch back to the virtual repository for installs:

```powershell
$env:JFROG_NPM_REGISTRY = "https://trialhnuk69.jfrog.io/artifactory/api/npm/funesterie-npm/"
.\scripts\jfrog\Write-JFrogNpmrc.ps1 -Force
```

The first publish set is intentionally conservative:

```txt
@funeste38/envaptex
@funeste38/bat
@funeste38/freeland
@funeste38/rome
@funeste38/qflush
@funeste38/allmight
```

Experimental packages are listed in
`scripts/jfrog/funesterie-packages.json` with `publish=false`.

By default, publish also uses `--ignore-scripts` so package lifecycle hooks such
as Husky do not break CI or leak local assumptions. If a package genuinely needs
npm lifecycle scripts during publish, add `-RunLifecycleScripts`.

## Install from JFrog

With `.npmrc.jfrog` and `JFROG_NPM_AUTH_TOKEN` loaded:

```powershell
npm install @funeste38/qflush --userconfig .\.npmrc.jfrog
npm install @funeste38/rome --userconfig .\.npmrc.jfrog
```

## Safety rules

- Never commit real JFrog tokens.
- Keep `jfrog.env.ps1`, `.npmrc.jfrog`, and local credentials ignored.
- Publish from the manifest, not by recursively scanning the whole repo.
- Keep Qflush as a module/package, not as a public `qflush.funesterie.pro`
  endpoint.
