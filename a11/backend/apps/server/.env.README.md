# Configuration A11 Backend

## Fichiers de configuration

- **`.env.local`** : Dev pur localhost (NEZ_SECURITY_MODE=off)
- **`.env.online`** : Backend exposé via Caddy/Free (NEZ_SECURITY_MODE=dev)

## Basculer entre les modes

### Mode local (dev pur)
```powershell
# Utiliser .env.local (déjà actif par défaut)
# NEZ_SECURITY_MODE=off → pas d'auth requise sur localhost
```

### Mode online (exposé via Caddy)
```powershell
# Copier .env.online vers .env.local
Copy-Item .env.online .env.local -Force

# Générer un JWT_SECRET sécurisé
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
# Copier le résultat dans JWT_SECRET dans .env.local
```

## Sécurité NEZ

Quand `NEZ_SECURITY_MODE=dev` :
- Les requêtes depuis localhost sont autorisées sans token
- Les requêtes externes nécessitent un token JWT (obtenu via `/api/auth/login`)
- Le frontend envoie automatiquement `X-NEZ-TOKEN` avec le JWT de session

Quand `NEZ_SECURITY_MODE=off` :
- Toutes les requêtes sont autorisées (dev uniquement)

## Routes protégées par Caddy

Le Caddyfile bloque déjà ces routes sensibles (403) :
- `/api/v1/vs/*` (VS Code bridge)
- `/api/v1/fs/*` (filesystem)
- `/api/admin/*` (admin)
- `/api/tools/run` (execution)
- `/api/browse*` (navigation)

Ces routes ne sont accessibles que depuis localhost, même avec NEZ activé.
