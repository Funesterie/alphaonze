# Changer le port SSH sans se verrouiller dehors

*2026-08-19.*

## Ce qui a change dans le repo

Le port n'est plus implicite. `deploy-a11-prod-finland-2.ps1` le passe
explicitement a chaque appel ssh, via `$sshBase` :

```
A11_HETZNER_SSH_PORT=52022     # ou -SshPort 52022
```

Defaut : 22. Rien ne change tant que la variable n'est pas posee.
`configure-neo4j.ps1` lit la meme variable.

C'etait le prealable : avant, deplacer sshd aurait casse le deploiement, parce
qu'aucun appel ne precisait de port.

## « Port dynamique » : ce que ça veut dire vraiment

Un port SSH qui change tout seul n'existe pas tel quel — le client doit savoir
ou frapper. Trois options, par cout croissant :

1. **Port fixe non standard** (52022, 2222…). Coupe le bruit : les balayages
   automatises visent le 22 et passent a cote. Ne protege pas d'un attaquant
   qui te vise : `nmap -p-` retrouve le port en quelques secondes.
2. **Port knocking.** Une sequence de paquets sur des ports fermes ouvre le vrai
   port. Simple, mais la sequence est rejouable par qui ecoute le reseau.
3. **SPA — Single Packet Authorization** (`fwknop`). Un paquet unique,
   authentifie et horodate, ouvre le port pour cette IP seulement, quelques
   secondes. C'est le seul des trois qui merite le mot « dynamique ». Le port
   reste invisible a un balayage : il est ferme tant que personne n'a frappe.

Sur ce qui protege vraiment, dans l'ordre : authentification par cle seule
(`PasswordAuthentication no`), `PermitRootLogin no`, fail2ban, et le pare-feu
cloud Hetzner. Le changement de port arrive loin derriere — il reduit le bruit
dans les logs, ce qui est deja utile pour voir les vraies tentatives.

## La procedure, sans coupure

Le risque est reel : mal fait, on perd l'acces au serveur definitivement. La
regle absolue est de **faire ecouter les deux ports en meme temps**, et de ne
retirer l'ancien qu'apres avoir prouve que le nouveau marche.

1. **Ne ferme jamais la session en cours.** Elle est le filet. Tout se verifie
   depuis un *second* terminal.

2. Ajouter le nouveau port sans retirer l'ancien, dans `/etc/ssh/sshd_config` :

   ```
   Port 22
   Port 52022
   ```

3. SELinux, si actif : `semanage port -a -t ssh_port_t -p tcp 52022`

4. Ouvrir le port cote pare-feu **du serveur** (`ufw allow 52022/tcp`) **et
   cote pare-feu cloud Hetzner** — les deux, sinon la connexion sera filtree en
   amont sans jamais atteindre la machine.

5. Recharger : `sudo sshd -t && sudo systemctl reload sshd`
   Le `-t` teste la configuration avant de l'appliquer ; sans lui, une faute de
   frappe suffit a tuer le service.

6. Depuis un second terminal, verifier :
   `ssh -p 52022 deploy@37.27.63.109`

7. Verifier aussi le deploiement, avec `A11_HETZNER_SSH_PORT=52022`, avant
   d'aller plus loin.

8. Seulement alors, retirer `Port 22`, recharger, refermer le port 22 au
   pare-feu. Et garder la premiere session ouverte jusqu'a ce qu'une nouvelle
   connexion sur le nouveau port ait reussi.

## Si l'acces est perdu malgre tout

Hetzner fournit une console KVM depuis le panneau cloud : elle donne un acces
clavier hors reseau, independant de sshd. C'est le vrai filet de securite —
verifier qu'on sait s'en servir **avant** de toucher au port, pas apres.
